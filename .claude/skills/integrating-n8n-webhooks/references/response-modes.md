# Режими відповіді вебхука n8n і URL

Читати, коли треба вирішити, чи чекати відповіді n8n, і коли йдеться про URL вебхука.

## Режими вузла Webhook

| Режим | Що отримує Next.js | Коли використовуємо |
|---|---|---|
| Immediately | 200 одразу після отримання запиту | Подія «до відома», результат не потрібен: `lead-created`, аналітика |
| When Last Node Finishes | Вихід останнього вузла після завершення воркфлоу | Швидкий запит довідки (секунди), коли результат потрібен у відповіді |
| Using Respond to Webhook | Те, що задає вузол Respond to Webhook (код, заголовки, тіло) | **Стандарт для довгих задач:** 202 `{"job_id": …}` одразу, результат — колбеком |
| Streaming | Потік відповіді | Не використовуємо |

**Правило:** усе, що може наблизитися до **100 секунд**, — лише асинхронно (202 + колбек). На n8n Cloud
запит, на який вебхук не відповів за 100 с, завершується кодом **524**; воркфлоу працює далі, а Next.js про
результат уже не дізнається. Якщо тривалість невідома — воркфлоу асинхронний.

- Respond to Webhook спрацьовує один раз; наступні такі вузли ігноруються.
- Якщо воркфлоу завершився, не дійшовши до Respond to Webhook (напр. Remove Duplicates відкинув повтор ще до
  нього), n8n відповідає 200 зі стандартним
  повідомленням; помилка до нього — 500.

## Тестовий і production URL

| | Тестовий URL | Production URL |
|---|---|---|
| Шлях | `/webhook-test/<path>` | `/webhook/<path>` |
| Коли працює | 120 с після «Listen for test event» у редакторі (або запуску воркфлоу) | Поки воркфлоу **опублікований** |
| Дані видно в редакторі | Так | Ні |

- У коді й `.env.example` — **лише** `/webhook`. Тестовий URL — тимчасово й лише у власному `.env.local`,
  коли дивитесь дані в редакторі n8n. Інакше заявки мовчки губляться, щойно хтось закриє редактор.
- n8n 2.x: публікація фіксує конкретну версію воркфлоу, production-виклики йдуть у неї, а не в останні
  правки. Після змін — опублікувати знову.
- Шляхи `webhook` і `webhook-test` на self-hosted n8n змінюють змінні `N8N_ENDPOINT_WEBHOOK` і
  `N8N_ENDPOINT_WEBHOOK_TEST`. Якщо клієнт це зробив — записати в `docs/n8n-integrations.md` проєкту.
